# Support

MeetingVault is prerelease software maintained by [RSI Tech](https://rsitech.ai) through GitHub. Community support is best effort; there is no guaranteed response time or compatibility support for forks and modified builds.

## Before opening an issue

1. Confirm the Mac is Apple silicon and runs macOS 26 or later.
2. Reproduce the problem on the latest published prerelease or the current `main` branch.
3. Review [Troubleshooting](docs/troubleshooting.md) and search existing issues.
4. Reduce the report to a synthetic or explicitly approved non-private fixture.

Open a bug report for a reproducible product defect. Use a feature request for a new workflow or behavior. Questions about building and contributing belong in a GitHub issue when the answer would help other contributors.

For a private project or conduct matter, contact [info@rsitech.ai](mailto:info@rsitech.ai). Use the dedicated private vulnerability route in [SECURITY.md](SECURITY.md) for suspected security or privacy vulnerabilities.

Do not attach meeting recordings, transcripts, credentials, signing material, recovery keys, or private logs. Suspected vulnerabilities and privacy failures must use the private process in [SECURITY.md](SECURITY.md).

## Support boundary

The project supports the platform and toolchain documented in [README.md](README.md). Apple service availability, organization-managed privacy controls, third-party forks, unreleased operating-system builds, and local signing or notarization credentials are outside the project's control. Reports are still useful when they clearly separate an app defect from one of those external conditions.
